# Task 118 DB-backed Schema Wiring Audit

审计时间：2026-05-20

## 范围与判定规则

本 artifact 支撑 `tasks.md` task 118：每个 DB-backed endpoint 必须能追溯到 `apps/type/src/business/**/schema.ts` 中的 Drizzle table、Zod schema 和 TypeScript 类型。

判定规则：

- `db-read-repository-wired-with-gap`：`apps/api/server/modules/*/repository.ts` 使用 `@01s-11comm/type` 导入 Drizzle table，并且对应 `apps/type/src/business/**/schema.ts` 同时存在 `pgTable`、`createInsertSchema`/`createSelectSchema`/必要 `update*Schema`、`$inferSelect`/`$inferInsert` 或 `z.infer` 类型。该状态只证明 schema 接线存在且仍带 gap，不证明生产 `DB_READY`、真实库样本、页面调用、fallback/shadow-off、写入读回回滚或退役。
- `schema-exists-not-wired`：`apps/type` 已有表/Zod/类型，但当前 `apps/api` endpoint 或方法仍未用 repository/service 接入该 schema，或仍返回 mock/fallback/in-memory 结果。
- `schema-missing`：当前 endpoint 声称或疑似 DB-backed，但未在 `apps/type/src/business/**/schema.ts` 找到对应业务表、Zod schema 和类型。缺 schema 时必须走独立 schema 变更流程，不得在旧 `apps/admin/server/db/schemas` 新增事实源。
- `unknown-needs-triage`：endpoint 或业务语义尚不能稳定映射到单一业务表或数据源，需要后续按 endpoint 逐条确认。
- `non-db-or-fallback`：health/debug/manifest、R2/mock upload、payment-like mock、legacy proxy、in-memory seed 或 guarded mutation，不进入 DB-backed 完成口径。

## 不得升级为完成的 no-go

- 不得把本 artifact 的 `db-read-repository-wired-with-gap` 写成 `DB_READY`、真实库样本通过、生产可用、shadow-off/fallback 完成或退役候选。
- 不得把 route 文件存在、runtime manifest 条目、HTTP 200、Vitest 通过、fallback proxy、in-memory seed 或 mock 返回写成 DB-backed 完成。
- 不得把 admin canonical endpoint 的 schema 接线外推为 app legacy endpoint 完成；app legacy 必须另有旧路径、method、response envelope、guard/fallback、调用端与浏览器/HTTP 证据。
- 不得把 read-only schema 接线外推为 create/update/delete、支付、开门、报修流转、审批、费用等写入口完成；写入口必须有 guard-before、controlled write、read-back、rollback/cleanup、residual check 和 guard-after。
- 缺 schema 或 schema 未接线时必须保持 `schema-missing`、`schema-exists-not-wired` 或 `unknown-needs-triage`，先走独立 schema 变更或 endpoint triage，不得在本 change 中夹带数据库 schema 改动。
