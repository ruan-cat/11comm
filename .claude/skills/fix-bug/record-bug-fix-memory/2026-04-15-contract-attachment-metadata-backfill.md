# 2026-04-15 合同附件元数据回填遗漏事故

## 1. 问题现象

`change` 业务新增或修改附件后，详情接口返回的附件记录里 `contractNumber` 和 `contractName` 为空，页面显示成不完整的文件说明。

## 2. 实际根因

服务端在把附件表记录物化成 `AttachmentDetailItem` 时，把合同元数据写死成空字符串，没有从所属合同记录透传。

## 3. 关键误导点

上传、保存、删除本身都能成功，容易让人误以为后端数据完整；实际上问题发生在 detail materialization，而不是上传链路。

## 4. 有效修复

在 `change-service.ts` 中构造附件详情时，把所属合同的 `contractNumber` 和 `contractName` 作为上下文统一传入 DB 链路和内存回退链路。

## 5. 验证方式

Nitro 测试显式断言附件详情返回正确的合同编号与合同名称；页面详情回显不再出现空值。

## 6. 后续约束

以后新增附件类返回结构时，要把"列表记录"和"详情 VO"分开检查，尤其注意物化层是否遗漏业务上下文字段。
