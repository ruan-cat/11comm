# 2026-05-26 软删除与唯一索引冲突事故

## 1. 问题现象

带软删除的表在用户删除记录后无法重新添加相同值，唯一索引报冲突。

## 2. 实际根因

标准唯一索引会将软删除记录（`deletedAt` 非空）纳入检查范围，违反了"删除后可重新添加"的业务预期。

## 3. 关键误导点

误认为软删除只是逻辑删除，不影响唯一性约束。实际上 PostgreSQL 的唯一索引默认检查所有行，包括已软删除行。

## 4. 有效修复

为唯一索引添加部分索引条件 `WHERE deleted_at IS NULL`，使唯一性检查仅覆盖未删除记录。

## 5. 验证方式

在数据库层验证唯一索引定义包含 `WHERE deleted_at IS NULL` 条件；软删除后重新插入相同值不报错。

## 6. 后续约束

所有带软删除的表的唯一索引必须添加 `WHERE deleted_at IS NULL` 条件。缺失外键约束的表需补全 `.references()` 定义。
