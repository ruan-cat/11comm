## 概述

本文档提供了 AI 代理与 Neon API 交互的一套综合规则和指南。Neon API 是一个 RESTful 服务，允许以编程方式管理所有 Neon 资源。遵守这些规则可确 API 使用的正确性、高效性和安全性。

### 通用 API 指南

所有 Neon API 请求必须发送到以下基本 URL：

```plain
https://console.neon.tech/api/v2/
```

要构建完整的请求 URL，请将特定的端点路径附加到此基本 URL。

### 身份验证

- 所有 API 请求必须使用 Neon API 密钥进行身份验证。
- API 密钥必须包含在 `Authorization` 标头中，使用 `Bearer` 身份验证方案。
- 标头格式应为：`Authorization: Bearer $NEON_API_KEY`，其中 `$NEON_API_KEY` 是有效的 Neon API 密钥。
- 没有有效 `Authorization` 标头的请求将失败，状态代码为 `401 Unauthorized`。

### API 速率限制

- Neon 将 API 请求限制为每分钟 700 个请求（约每秒 11 个）。
- 允许每个路由每秒最多爆发 40 个请求。
- 如果超过速率限制，API 将响应 `HTTP 429 Too Many Requests` 错误。
- 您的应用程序逻辑必须处理 `429` 错误并实施具有适当退避的重试策略。

### Neon 核心概念

要有效地使用 Neon Python SDK，必须了解其核心资源的层次结构和用途。下表提供了每个概念的高级概述。

| 概念     | 描述                                                                           | 类比/用途                                                          | 关键关系                                                                |
| -------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 组织     | 最高级别的容器，管理计费、用户和多个项目。                                     | GitHub 组织或公司的云帐户。                                        | 包含一个或多个项目。                                                    |
| 项目     | 包含单个应用程序或服务的所有相关数据库资源的主要容器。                         | Git 存储库或应用程序的顶级文件夹。                                 | 存在于组织（或个人帐户）内。包含分支。                                  |
| 分支     | 数据库状态在特定时间点的轻量级、写时复制克隆。                                 | `git branch`。用于隔离开发、测试、暂存或预览，而无需重复存储成本。 | 属于项目。包含自己的一组数据库和角色，从其父级克隆。                    |
| 计算端点 | 您连接到的实际运行的 PostgreSQL 实例。它为处理查询提供 CPU 和 RAM。            | 数据库的“服务器”或“引擎”。它可以启动、暂停（缩放至零）和调整大小。 | 附加到单个分支。您的连接字符串指向计算端点的主机名。                    |
| 数据库   | 分支内数据的逻辑容器（表、模式、视图）。它遵循标准的 PostgreSQL 约定。         | PostgreSQL 服务器实例内的单个数据库。                              | 存在于分支内。一个分支可以有多个数据库。                                |
| 角色     | 用于身份验证（登录）和授权（访问数据的权限）的 PostgreSQL 角色。               | 具有用户名和密码的数据库用户帐户。                                 | 属于分支。父分支的角色在创建时复制到子分支。                            |
| API 密钥 | 用于验证 Neon API 请求的秘密令牌。密钥具有不同的范围（个人、组织、项目范围）。 | 程序化访问的密码，允许您管理所有其他 Neon 资源。                   | 验证对组织、项目、分支等的操作。                                        |
| 操作     | Neon 控制平面执行的异步操作，例如创建分支或启动计算。                          | 后台作业或任务。可以轮询其状态以了解操作何时完成。                 | 与项目相关联，通常与特定分支或端点相关联。对于脚本化 API 调用至关重要。 |

### 了解 API 密钥类型

通过 API 执行操作时，必须根据所需的范围和权限选择���确的 API 密钥类型。共有三种类型：

1. 个人 API 密钥

- 范围：访问创建密钥的用户所属的所有项目。
- 权限：密钥具有与其所有者相同的权限。如果用户的访问权限从组织中撤销，密钥也会失去访问权限。
- 最适合：个人使用、脚本编写以及与特定用户权限绑定的任务。
- 创建者：任何用户。

2. 组织 API 密钥

- 范围：访问整个组织内的所有项目和资源。
- 权限：具有跨组织的管理员级访问权限，独立于任何单个用户。即创建者离开组织，它仍然有效。
- 最适合：CI/CD 管道、全组织自动化以及需要广泛访问权限的服务帐户。
- 创建者：仅限组织管理员。

3. 项目范围 API 密钥

- 范围：访问严格限制在单个指定项目。
- 权限：无法执行组织级操作（如创建新项目）或删除其范围内的项目。这是最安全和受限的密钥类型。
- 最适合：项目特定的集成、第三方服务或应隔离到一个项目的自动化。
- 创建者：任何组织成员。
